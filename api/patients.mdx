The Patients API lets you manage the core demographic records at the heart of the EHR platform. You can search for existing patients, register new ones, and update contact or insurance information — all through a straightforward set of REST endpoints. Every patient record is assigned a unique immutable `id` that you use to associate appointments, encounters, prescriptions, and billing claims.

## List Patients — `GET /patients`

Retrieve a paginated list of patients. Use the `search` parameter to perform a full-text search across first name, last name, date of birth, and email.

```bash
curl -X GET "https://api.example-ehr.com/v1/patients?search=smith&limit=20" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

### Query Parameters

<ParamField query="search" type="string">
  Full-text search string. Matches against `first_name`, `last_name`,
  `date_of_birth`, and `email`.
</ParamField>

<ParamField query="limit" type="integer">
  Number of results to return per page. Defaults to `20`; maximum is `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Opaque pagination cursor returned in the previous response as `next_cursor`.
  Omit to start from the first page.
</ParamField>

### Response

```json
{
  "data": [
    {
      "id": "pat_01HX9KZMQE4T2V8PNBR7WD3CF",
      "first_name": "Jane",
      "last_name": "Smith",
      "date_of_birth": "1985-04-12",
      "gender": "female",
      "email": "jane.smith@email.example",
      "phone": "+15105550192",
      "created_at": "2024-01-15T09:30:00Z"
    }
  ],
  "next_cursor": "eyJpZCI6InBhdF8wMUhYOUtaTVFFNFQyVjhQTkJSN1dEM0NGIn0",
  "total": 142
}
```

## Create a Patient — `POST /patients`

Register a new patient record. The fields `first_name`, `last_name`, `date_of_birth`, and `gender` are required.

```bash
curl -X POST https://api.example-ehr.com/v1/patients \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "first_name": "Marcus",
    "last_name": "Rivera",
    "date_of_birth": "1990-07-23",
    "gender": "male",
    "email": "marcus.rivera@email.example",
    "phone": "+14155550143",
    "address": {
      "line1": "742 Evergreen Terrace",
      "city": "Springfield",
      "state": "IL",
      "postal_code": "62701",
      "country": "US"
    }
  }'
```

### Request Body

<ParamField body="first_name" type="string" required>
  Patient's legal first name.
</ParamField>

<ParamField body="last_name" type="string" required>
  Patient's legal last name.
</ParamField>

<ParamField body="date_of_birth" type="string" required>
  Date of birth in **ISO 8601** format (`YYYY-MM-DD`).
</ParamField>

<ParamField body="gender" type="string" required>
  Patient's gender. Accepted values: `"male"`, `"female"`, `"non_binary"`,
  `"other"`, `"prefer_not_to_say"`.
</ParamField>

<ParamField body="email" type="string">
  Patient's email address. Must be a valid email format.
</ParamField>

<ParamField body="phone" type="string">
  Patient's phone number in **E.164** format (e.g., `+15105550192`).
</ParamField>

<ParamField body="address" type="object">
  Patient's mailing address.

  <Expandable title="address fields">
    <ParamField body="address.line1" type="string">
      Street address line 1.
    </ParamField>

    <ParamField body="address.line2" type="string">
      Street address line 2 (apartment, suite, etc.).
    </ParamField>

    <ParamField body="address.city" type="string">
      City.
    </ParamField>

    <ParamField body="address.state" type="string">
      Two-letter US state code or full state/province name.
    </ParamField>

    <ParamField body="address.postal_code" type="string">
      ZIP or postal code.
    </ParamField>

    <ParamField body="address.country" type="string">
      ISO 3166-1 alpha-2 country code (e.g., `"US"`).
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="insurance" type="object">
  Primary insurance information.

  <Expandable title="insurance fields">
    <ParamField body="insurance.provider_name" type="string">
      Name of the insurance provider.
    </ParamField>

    <ParamField body="insurance.member_id" type="string">
      Member / subscriber ID on the insurance card.
    </ParamField>

    <ParamField body="insurance.group_number" type="string">
      Group number on the insurance card.
    </ParamField>
  </Expandable>
</ParamField>

### Response

Returns HTTP `201 Created` with the newly created patient object.

```json
{
  "id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
  "first_name": "Marcus",
  "last_name": "Rivera",
  "date_of_birth": "1990-07-23",
  "gender": "male",
  "email": "marcus.rivera@email.example",
  "phone": "+14155550143",
  "address": {
    "line1": "742 Evergreen Terrace",
    "city": "Springfield",

    "postal_code": "62701",
    "country": "US"
  },
  "insurance": null,
  "created_at": "2024-06-10T14:22:05Z",
  "updated_at": "2024-06-10T14:22:05Z"
}
```

## Get a Patient — `GET /patients/{id}`

Retrieve the full record for a single patient by their unique ID.

```bash
curl -X GET https://api.example-ehr.com/v1/patients/pat_01HXB3FKVN8QT5WP2YDMCZ7RS \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

### Path Parameters

<ParamField path="id" type="string" required>
  The unique patient ID (prefixed `pat_`).
</ParamField>

### Response

Returns HTTP `200 OK` with the complete patient object.

```json

  "id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
  "first_name": "Marcus",
  "last_name": "Rivera",
  "date_of_birth": "1990-07-23",
  "gender": "male",
  "email": "marcus.rivera@email.example",
  "phone": "+14155550143",
  "address": {
    "line1": "742 Evergreen Terrace",
    "line2": null,
    "city": "Springfield",
    "state": "IL",
    "postal_code": "62701",
    "country": "US"
  },
  "insurance": {
    "provider_name": "BlueCross BlueShield",
    "member_id": "XYZ123456789",

  },
  "created_at": "2024-06-10T14:22:05Z",
  "updated_at": "2024-06-11T09:05:30Z"

```

## Update a Patient — `PUT /patients/{id}`

Update one or more fields on an existing patient record. Only the fields you include in the request body are changed — all other fields remain unchanged (partial update semantics).

```bash
curl -X PUT https://api.example-ehr.com/v1/patients/pat_01HXB3FKVN8QT5WP2YDMCZ7RS \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "m.rivera.new@email.example",
    "phone": "+14155550199",
    "insurance": {
      "provider_name": "Aetna",
      "member_id": "AET987654321",
      "group_number": "GRP1100"
    }
  }'
```

### Path Parameters

<ParamField path="id" type="string" required>
  The unique patient ID to update.
</ParamField>

### Request Body

All fields are optional. Include only the fields you want to update.

<ParamField body="first_name" type="string">
  Updated first name.
</ParamField>

<ParamField body="last_name" type="string">
  Updated last name.
</ParamField>

<ParamField body="date_of_birth" type="string">
  Updated date of birth in ISO 8601 format.
</ParamField>

<ParamField body="gender" type="string">
  Updated gender value.
</ParamField>

<ParamField body="email" type="string">
  Updated email address.
</ParamField>

<ParamField body="phone" type="string">
  Updated phone number in E.164 format.
</ParamField>

<ParamField body="address" type="object">
  Updated address object. Replaces the entire existing address when provided.
</ParamField>

<ParamField body="insurance" type="object">
  Updated insurance object. Replaces the entire existing insurance record when
  provided.
</ParamField>

### Response

Returns HTTP `200 OK` with the fully updated patient object in the same shape as `GET /patients/{id}`.

<Note>
  The `id`, `created_at`, and any fields not included in the request body are
  left unchanged. To clear an optional field, explicitly pass `null`.
</Note>
