The Clinical Data API gives you programmatic access to the clinical layer of the EHR platform — structured encounter notes, prescriptions, and diagnostic orders. These endpoints power downstream clinical workflows: you can create encounter records during or after a visit, attach SOAP notes, issue prescriptions to connected pharmacies, and place lab or imaging orders with integrated diagnostic partners. Because these endpoints handle protected health information (PHI), every request must be authenticated and transmitted over HTTPS.

<Note>
  **HIPAA compliance reminder:** If you store or cache any data returned by
  these endpoints in an external system, that system must be covered by a signed
  Business Associate Agreement (BAA) with your organization. Do not log raw API
  responses containing PHI to unencrypted log sinks, error trackers, or
  analytics platforms without appropriate safeguards.
</Note>

## Encounters

A clinical encounter represents a single patient–provider interaction and is the primary container for visit notes, diagnoses, and treatment decisions.

### List Encounters — `GET /clinical/encounters`

Retrieve a paginated list of encounters. You must filter by `patient_id` to return results.

```bash
curl -X GET "https://api.example-ehr.com/v1/clinical/encounters?patient_id=pat_01HXB3FKVN8QT5WP2YDMCZ7RS&limit=10" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

#### Query Parameters

<ParamField query="patient_id" type="string" required>
  Return only encounters for this patient ID.
</ParamField>

<ParamField query="provider_id" type="string">
  Further filter by the provider who conducted the encounter.
</ParamField>

<ParamField query="date_from" type="string">
  Return encounters with an `encounter_date` on or after this ISO 8601 date
  (e.g., `"2024-01-01"`).
</ParamField>

<ParamField query="date_to" type="string">
  Return encounters with an `encounter_date` on or before this ISO 8601 date.
</ParamField>

<ParamField query="limit" type="integer">
  Number of results per page. Defaults to `20`; maximum is `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor from the previous response's `next_cursor` field.
</ParamField>

#### Response

```json
{
  "data": [
    {
      "id": "enc_01HZ7DPKQX3NW8BF6VCGMYTRS",
      "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
      "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
      "appointment_id": "appt_01HYCD5MNP2RW6QK8XJBT4VES",
      "encounter_date": "2024-07-15",
      "visit_type": "follow_up",
      "status": "signed",
      "created_at": "2024-07-15T11:45:00Z"
    }
  ],
  "next_cursor": null,
  "total": 1
}
```

### Create an Encounter — `POST /clinical/encounters`

Open a new encounter record for a patient visit. You can attach the encounter to an existing appointment or create a standalone record.

```bash
curl -X POST https://api.example-ehr.com/v1/clinical/encounters \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
    "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
    "appointment_id": "appt_01HYCD5MNP2RW6QK8XJBT4VES",
    "encounter_date": "2024-07-15",
    "visit_type": "follow_up",
    "note": {
      "subjective": "Patient reports improved blood pressure control. No chest pain.",
      "objective": "BP 128/82, HR 72, Weight 185 lbs.",
      "assessment": "Hypertension, well-controlled on current regimen.",
      "plan": "Continue lisinopril 10mg daily. Follow up in 3 months."
    },
    "diagnoses": [
      { "code": "I10", "system": "ICD-10-CM", "description": "Essential hypertension" }
    ]
  }'
```

#### Request Body

<ParamField body="patient_id" type="string" required>
  The ID of the patient this encounter belongs to.
</ParamField>

<ParamField body="provider_id" type="string" required>
  The ID of the provider conducting the encounter.
</ParamField>

<ParamField body="encounter_date" type="string" required>
  Date of the encounter in ISO 8601 format (`YYYY-MM-DD`).
</ParamField>

<ParamField body="visit_type" type="string" required>
  Type of visit (e.g., `"new_patient"`, `"follow_up"`, `"urgent_care"`).
</ParamField>

<ParamField body="appointment_id" type="string">
  ID of the associated appointment. Links the encounter to the scheduling
  record. Optional for walk-in or standalone encounters.
</ParamField>

<ParamField body="note" type="object">
  Structured SOAP note content.

  <Expandable title="note fields">
    <ParamField body="note.subjective" type="string">
      Patient's reported symptoms and chief complaint (Subjective).
    </ParamField>
    <ParamField body="note.objective" type="string">
      Provider's objective observations, vital signs, and exam findings.
    </ParamField>
    <ParamField body="note.assessment" type="string">
      Clinical assessment and differential diagnosis.
    </ParamField>
    <ParamField body="note.plan" type="string">
      Treatment plan, follow-up instructions, and next steps.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="diagnoses" type="array">
  Array of diagnosis objects attached to this encounter.

  <Expandable title="diagnosis fields">
    <ParamField body="diagnoses[].code" type="string">
      Diagnostic code (e.g., `"I10"`).
    </ParamField>
    <ParamField body="diagnoses[].system" type="string">
      Coding system: `"ICD-10-CM"`, `"SNOMED-CT"`, or `"ICD-9-CM"`.
    </ParamField>
    <ParamField body="diagnoses[].description" type="string">
      Human-readable description of the diagnosis.
    </ParamField>
  </Expandable>
</ParamField>

#### Response

Returns HTTP `201 Created` with the new encounter object. The `status` is initially `"draft"` until the provider signs it.

```json
{
  "id": "enc_01HZ7DPKQX3NW8BF6VCGMYTRS",
  "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
  "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
  "appointment_id": "appt_01HYCD5MNP2RW6QK8XJBT4VES",
  "encounter_date": "2024-07-15",
  "visit_type": "follow_up",
  "status": "draft",
  "note": {
    "subjective": "Patient reports improved blood pressure control. No chest pain.",
    "objective": "BP 128/82, HR 72, Weight 185 lbs.",
    "assessment": "Hypertension, well-controlled on current regimen.",
    "plan": "Continue lisinopril 10mg daily. Follow up in 3 months."
  },
  "diagnoses": [
    { "code": "I10", "system": "ICD-10-CM", "description": "Essential hypertension" }
  ],
  "created_at": "2024-07-15T11:45:00Z",
  "updated_at": "2024-07-15T11:45:00Z"
}
```

### Get an Encounter — `GET /clinical/encounters/{id}`

Retrieve the full encounter record, including the complete note content and diagnoses list.

```bash
curl -X GET https://api.example-ehr.com/v1/clinical/encounters/enc_01HZ7DPKQX3NW8BF6VCGMYTRS \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

#### Path Parameters

<ParamField path="id" type="string" required>
  The unique encounter ID (prefixed `enc_`).
</ParamField>

#### Response Fields

<ResponseField name="id" type="string">
  Unique encounter identifier.
</ResponseField>

<ResponseField name="patient_id" type="string">
  ID of the associated patient.
</ResponseField>

<ResponseField name="provider_id" type="string">
  ID of the provider who conducted the encounter.
</ResponseField>

<ResponseField name="appointment_id" type="string">
  ID of the linked appointment, or `null` for standalone encounters.
</ResponseField>

<ResponseField name="encounter_date" type="string">
  Date of the encounter in ISO 8601 format.
</ResponseField>

<ResponseField name="visit_type" type="string">
  Type of visit.
</ResponseField>

<ResponseField name="status" type="string">
  Encounter status: `"draft"`, `"signed"`, or `"amended"`.
</ResponseField>

<ResponseField name="note" type="object">
  Full SOAP note with `subjective`, `objective`, `assessment`, and `plan` fields.
</ResponseField>

<ResponseField name="diagnoses" type="array">
  Array of diagnosis objects with `code`, `system`, and `description`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp when the encounter was created.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the most recent update.
</ResponseField>

## Prescriptions

### Create a Prescription — `POST /prescriptions`

Send a prescription to the patient's preferred pharmacy via the connected e-prescribing network.

```bash
curl -X POST https://api.example-ehr.com/v1/prescriptions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
    "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
    "encounter_id": "enc_01HZ7DPKQX3NW8BF6VCGMYTRS",
    "medication_name": "Lisinopril",
    "dosage": "10mg",
    "frequency": "once daily",
    "quantity": 30,
    "refills": 3,
    "instructions": "Take by mouth in the morning.",
    "pharmacy_ncpdp_id": "1234567"
  }'
```

#### Request Body

<ParamField body="patient_id" type="string" required>
  The ID of the patient receiving the prescription.
</ParamField>

<ParamField body="provider_id" type="string" required>
  The ID of the prescribing provider. The provider must have a valid DEA or
  state license on file.
</ParamField>

<ParamField body="medication_name" type="string" required>
  Name of the medication (generic or brand).
</ParamField>

<ParamField body="dosage" type="string" required>
  Dosage amount and unit (e.g., `"10mg"`, `"500mg/5mL"`).
</ParamField>

<ParamField body="frequency" type="string" required>
  Frequency of administration (e.g., `"once daily"`, `"twice daily"`, `"every 8 hours"`).
</ParamField>

<ParamField body="quantity" type="integer" required>
  Number of units or volume to dispense.
</ParamField>

<ParamField body="refills" type="integer" required>
  Number of authorized refills (use `0` for no refills).
</ParamField>

<ParamField body="encounter_id" type="string">
  ID of the encounter to associate this prescription with.
</ParamField>

<ParamField body="instructions" type="string">
  Additional dispensing or patient instructions printed on the label.
</ParamField>

<ParamField body="pharmacy_ncpdp_id" type="string">
  NCPDP ID of the target pharmacy. If omitted, the prescription is sent to the
  patient's preferred pharmacy on file.
</ParamField>

#### Response

Returns HTTP `201 Created` with the prescription record and its transmission status.

```json
{
  "id": "rx_01HZFMTPKQ4WV9NBCR2XJD8SG",
  "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
  "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
  "encounter_id": "enc_01HZ7DPKQX3NW8BF6VCGMYTRS",
  "medication_name": "Lisinopril",
  "dosage": "10mg",
  "frequency": "once daily",
  "quantity": 30,
  "refills": 3,
  "instructions": "Take by mouth in the morning.",
  "pharmacy_ncpdp_id": "1234567",
  "transmission_status": "sent",
  "created_at": "2024-07-15T12:10:00Z"
}
```

## Lab Orders

### Place a Lab Order — `POST /orders/lab`

Submit a laboratory order to a connected diagnostic lab for processing.

```bash
curl -X POST https://api.example-ehr.com/v1/orders/lab \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
    "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
    "encounter_id": "enc_01HZ7DPKQX3NW8BF6VCGMYTRS",
    "tests": [
      { "code": "2093-3", "system": "LOINC", "name": "Total Cholesterol" },
      { "code": "2085-9", "system": "LOINC", "name": "HDL Cholesterol" }
    ],
    "priority": "routine",
    "clinical_notes": "Fasting lipid panel for annual wellness visit.",
    "lab_id": "lab_01HW2MPQR8NK5FBZ7XCTE3VA"
  }'
```

#### Request Body

<ParamField body="patient_id" type="string" required>
  The ID of the patient for whom the lab is ordered.
</ParamField>

<ParamField body="provider_id" type="string" required>
  The ID of the ordering provider.
</ParamField>

<ParamField body="tests" type="array" required>
  One or more test objects. Each test requires a `code`, `system`, and `name`.

  <Expandable title="test fields">
    <ParamField body="tests[].code" type="string">
      Standardized test code (e.g., LOINC code).
    </ParamField>
    <ParamField body="tests[].system" type="string">
      Coding system: `"LOINC"` or `"CPT"`.
    </ParamField>
    <ParamField body="tests[].name" type="string">
      Human-readable test name.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="priority" type="string" required>
  Order priority: `"routine"` or `"stat"`.
</ParamField>

<ParamField body="encounter_id" type="string">
  ID of the associated encounter.
</ParamField>

<ParamField body="clinical_notes" type="string">
  Clinical context or instructions for the lab.
</ParamField>

<ParamField body="lab_id" type="string">
  ID of the specific lab to route this order to. If omitted, the order routes
  to the default lab configured in your organization settings.
</ParamField>

#### Response

Returns HTTP `201 Created` with the lab order record.

```json
{
  "id": "order_01HZGPBNQ5MX8WRTK3DCVF7YJ",
  "type": "lab",
  "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
  "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
  "encounter_id": "enc_01HZ7DPKQX3NW8BF6VCGMYTRS",
  "tests": [
    { "code": "2093-3", "system": "LOINC", "name": "Total Cholesterol" },
    { "code": "2085-9", "system": "LOINC", "name": "HDL Cholesterol" }
  ],
  "priority": "routine",
  "status": "submitted",
  "created_at": "2024-07-15T12:30:00Z"
}
```

<Tip>
  Use `"priority": "stat"` only for clinically urgent orders. Stat orders
  may incur additional processing fees with connected lab partners.
</Tip>

## Imaging Orders

### Place an Imaging Order — `POST /orders/imaging`

Submit a diagnostic imaging order to a connected radiology provider.

```bash
curl -X POST https://api.example-ehr.com/v1/orders/imaging \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
    "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
    "encounter_id": "enc_01HZ7DPKQX3NW8BF6VCGMYTRS",
    "modality": "X-RAY",
    "body_region": "Chest",
    "study_description": "PA and Lateral Chest X-Ray",
    "cpt_code": "71046",
    "clinical_indication": "Evaluate for pneumonia. Patient presents with productive cough and fever.",
    "priority": "routine"
  }'
```

#### Request Body

<ParamField body="patient_id" type="string" required>
  The ID of the patient for whom the imaging is ordered.
</ParamField>

<ParamField body="provider_id" type="string" required>
  The ID of the ordering provider.
</ParamField>

<ParamField body="modality" type="string" required>
  Imaging modality. Common values: `"X-RAY"`, `"CT"`, `"MRI"`, `"ULTRASOUND"`,
  `"PET"`, `"MAMMOGRAPHY"`.
</ParamField>

<ParamField body="body_region" type="string" required>
  Anatomical region to be imaged (e.g., `"Chest"`, `"Abdomen"`, `"Left Knee"`).
</ParamField>

<ParamField body="study_description" type="string" required>
  Full description of the imaging study as it will appear on the order.
</ParamField>

<ParamField body="cpt_code" type="string" required>
  CPT procedure code for the imaging study (e.g., `"71046"` for PA and Lateral
  Chest X-Ray).
</ParamField>

<ParamField body="clinical_indication" type="string" required>
  Clinical reason or indication for the imaging order. Required for insurance
  authorization.
</ParamField>

<ParamField body="priority" type="string" required>
  Order priority: `"routine"` or `"stat"`.
</ParamField>

<ParamField body="encounter_id" type="string">
  ID of the associated encounter.
</ParamField>

#### Response

Returns HTTP `201 Created` with the imaging order record.

```json
{
  "id": "order_01HZHR2TKP6QM9XWBF4NCVD8Y",
  "type": "imaging",
  "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
  "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
  "encounter_id": "enc_01HZ7DPKQX3NW8BF6VCGMYTRS",
  "modality": "X-RAY",
  "body_region": "Chest",
  "study_description": "PA and Lateral Chest X-Ray",
  "cpt_code": "71046",
  "clinical_indication": "Evaluate for pneumonia. Patient presents with productive cough and fever.",
  "priority": "routine",
  "status": "submitted",
  "created_at": "2024-07-15T12:45:00Z"
}
```

<ResponseField name="id" type="string">
  Unique order identifier.
</ResponseField>

<ResponseField name="type" type="string">
  Order type: `"lab"` or `"imaging"`.
</ResponseField>

<ResponseField name="status" type="string">
  Current order status: `"submitted"`, `"scheduled"`, `"completed"`, or
  `"cancelled"`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp when the order was placed.
</ResponseField>
