Every request to the EHR API must be authenticated. The platform supports two complementary approaches: a long-lived **API key** that you embed directly in the `Authorization` header, and a short-lived **access token** obtained by calling the `/auth/token` endpoint. Both methods use the standard Bearer token scheme, so you can choose the approach that best fits your integration architecture.

<Warning>
  Treat your API keys and access tokens like passwords. Never expose them in
  client-side code, public repositories, or log files. If a key is compromised,
  revoke it immediately from **Settings → API Keys** and issue a new one.
</Warning>

## Generating an API Key

You create and manage API keys directly from the dashboard — no API call required.

1. Log in to the EHR dashboard and navigate to **Settings → API Keys**.
2. Click **Create API Key**.
3. Give the key a descriptive name (e.g., `billing-integration-prod`) so you can identify it later.
4. Copy the key immediately — it is displayed **only once** at creation time. Store it in a secrets manager or environment variable.
5. Optionally restrict the key to specific IP addresses or permission scopes.

<Note>
  API keys inherit the permissions of the user account that created them. Use a
  dedicated service account with the minimum required permissions when creating
  keys for automated integrations.
</Note>

## Using an API Key in Requests

Include your API key as a Bearer token in the `Authorization` header of every HTTP request:

```bash
curl -X GET https://api.example-ehr.com/v1/patients \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

If the header is missing or the key is invalid, the API returns a `401 Unauthorized` response:

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid or missing Authorization header."
  }
}
```

<Tip>
  Store your API key in an environment variable (e.g., `EHR_API_KEY`) and
  reference it in your code rather than hard-coding the value. For example:
  `Authorization: Bearer $EHR_API_KEY`.
</Tip>

## Token Exchange — `POST /auth/token`

For integrations that require short-lived credentials — such as delegating temporary access to a third-party service — you can exchange your API key (or a username and password) for a short-lived access token.

**Endpoint:** `POST https://api.example-ehr.com/v1/auth/token`

### Request

```bash
curl -X POST https://api.example-ehr.com/v1/auth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "api_key",
    "api_key": "YOUR_API_KEY"
  }'
```

You can also exchange a username and password by using `grant_type: "password"`:

```bash
curl -X POST https://api.example-ehr.com/v1/auth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "password",
    "username": "admin@clinic.example",
    "password": "your-password"
  }'
```

#### Request Fields

<ParamField body="grant_type" type="string" required>
  The credential type to exchange. Accepted values: `"api_key"` or
  `"password"`.
</ParamField>

<ParamField body="api_key" type="string">
  Your long-lived API key. Required when `grant_type` is `"api_key"`.
</ParamField>

<ParamField body="username" type="string">
  The account email address. Required when `grant_type` is `"password"`.
</ParamField>

<ParamField body="password" type="string">
  The account password. Required when `grant_type` is `"password"`.
</ParamField>

### Response

A successful request returns HTTP `200` with the following body:

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "read write"
}
```

#### Response Fields

<ResponseField name="access_token" type="string">
  The short-lived JWT access token. Use this as the Bearer token in subsequent
  API requests.
</ResponseField>

<ResponseField name="token_type" type="string">
  Always `"Bearer"`.
</ResponseField>

<ResponseField name="expires_in" type="integer">
  Token lifetime in seconds. Tokens expire after **3,600 seconds** (1 hour).
  Request a new token before expiry to maintain uninterrupted access.
</ResponseField>

<ResponseField name="scope" type="string">
  Space-separated list of permission scopes granted to this token.
</ResponseField>

Use the returned `access_token` exactly like a static API key:

```bash
curl -X GET https://api.example-ehr.com/v1/patients \
  -H "Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -H "Content-Type: application/json"
```

## Revoking API Keys

Revoke a key at any time from **Settings → API Keys** in the dashboard:

1. Locate the key you want to revoke in the list.
2. Click the **⋯** menu next to the key name and select **Revoke**.
3. Confirm the action in the dialog.

Revocation is **immediate** — any request made with the revoked key returns `401 Unauthorized` from that point forward. Active access tokens issued from the revoked key continue to work until they expire (up to 1 hour). If you need to invalidate tokens immediately, contact support to request a forced session termination.

<Warning>
  Revoking an API key cannot be undone. If you revoke a key that is still in
  active use, the dependent integration will lose access immediately. Rotate
  keys by creating a replacement first, updating your integration, and then
  revoking the old key.
</Warning>
