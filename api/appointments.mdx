The Appointments API lets you build scheduling workflows directly into your application. You can query the calendar by patient, provider, date range, or status; create new appointments; reschedule existing ones; and cancel visits — all with a single, consistent API. Appointments link patients to providers and form the entry point for clinical encounters and billing claims.

## Appointment Status Values

All appointment records carry a `status` field. The table below lists every valid value and when it applies.

| Status        | Description                                                                 |
| ------------- | --------------------------------------------------------------------------- |
| `scheduled`   | The appointment is confirmed and upcoming.                                  |
| `confirmed`   | The patient has confirmed attendance (e.g., via reminder reply).            |
| `checked_in`  | The patient has arrived and checked in at the front desk.                   |
| `in_progress` | The provider is currently seeing the patient.                               |
| `completed`   | The visit has concluded.                                                    |
| `cancelled`   | The appointment was cancelled by the patient or practice.                   |
| `no_show`     | The patient did not attend and did not cancel.                              |

## List Appointments — `GET /appointments`

Retrieve a paginated list of appointments. Filter by patient, provider, date range, or status to narrow results.

```bash
curl -X GET "https://api.example-ehr.com/v1/appointments?patient_id=pat_01HXB3FKVN8QT5WP2YDMCZ7RS&status=scheduled&limit=20" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

### Query Parameters

<ParamField query="patient_id" type="string">
  Filter results to appointments for a specific patient ID.
</ParamField>

<ParamField query="provider_id" type="string">
  Filter results to appointments assigned to a specific provider ID.
</ParamField>

<ParamField query="date_from" type="string">
  Return only appointments with a `start_time` on or after this ISO 8601
  datetime (e.g., `2024-06-01T00:00:00Z`).
</ParamField>

<ParamField query="date_to" type="string">
  Return only appointments with a `start_time` on or before this ISO 8601
  datetime (e.g., `2024-06-30T23:59:59Z`).
</ParamField>

<ParamField query="status" type="string">
  Filter by appointment status. See the [status values](#appointment-status-values) table above.
</ParamField>

<ParamField query="limit" type="integer">
  Number of results per page. Defaults to `20`; maximum is `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor from the previous response's `next_cursor` field.
</ParamField>

### Response

```json
{
  "data": [
    {
      "id": "appt_01HYCD5MNP2RW6QK8XJBT4VES",
      "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
      "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
      "start_time": "2024-07-15T10:00:00Z",
      "end_time": "2024-07-15T10:30:00Z",
      "visit_type": "follow_up",
      "status": "scheduled",
      "notes": "Patient follow-up for hypertension management.",
      "created_at": "2024-06-10T14:55:00Z",
      "updated_at": "2024-06-10T14:55:00Z"
    }
  ],
  "next_cursor": null,
  "total": 1
}
```

## Create an Appointment — `POST /appointments`

Schedule a new appointment by providing the patient, provider, time window, and visit type.

```bash
curl -X POST https://api.example-ehr.com/v1/appointments \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
    "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
    "start_time": "2024-07-15T10:00:00Z",
    "end_time": "2024-07-15T10:30:00Z",
    "visit_type": "follow_up",
    "notes": "Patient follow-up for hypertension management."
  }'
```

### Request Body

<ParamField body="patient_id" type="string" required>
  The ID of the patient for this appointment.
</ParamField>

<ParamField body="provider_id" type="string" required>
  The ID of the provider (physician, nurse practitioner, etc.) conducting the
  visit.
</ParamField>

<ParamField body="start_time" type="string" required>
  Appointment start time in ISO 8601 UTC format (e.g.,
  `"2024-07-15T10:00:00Z"`).
</ParamField>

<ParamField body="end_time" type="string" required>
  Appointment end time in ISO 8601 UTC format. Must be after `start_time`.
</ParamField>

<ParamField body="visit_type" type="string" required>
  The type of visit. Common values: `"new_patient"`, `"follow_up"`,
  `"annual_wellness"`, `"urgent_care"`, `"telehealth"`.
</ParamField>

<ParamField body="notes" type="string">
  Optional free-text scheduling notes visible to the provider and front desk.
</ParamField>

### Response

Returns HTTP `201 Created` with the full appointment object.

```json
{
  "id": "appt_01HYCD5MNP2RW6QK8XJBT4VES",
  "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
  "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
  "start_time": "2024-07-15T10:00:00Z",
  "end_time": "2024-07-15T10:30:00Z",
  "visit_type": "follow_up",
  "status": "scheduled",
  "notes": "Patient follow-up for hypertension management.",
  "created_at": "2024-06-10T14:55:00Z",
  "updated_at": "2024-06-10T14:55:00Z"
}
```

<Tip>
  To prevent double-booking, check for existing `scheduled` or `confirmed`
  appointments in the target time window using `GET /appointments` with
  `provider_id`, `date_from`, and `date_to` before creating a new one.
</Tip>

## Get an Appointment — `GET /appointments/{id}`

Retrieve the full details of a single appointment by its ID.

```bash
curl -X GET https://api.example-ehr.com/v1/appointments/appt_01HYCD5MNP2RW6QK8XJBT4VES \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

### Path Parameters

<ParamField path="id" type="string" required>
  The unique appointment ID (prefixed `appt_`).
</ParamField>

### Response Fields

<ResponseField name="id" type="string">
  Unique, immutable appointment identifier.
</ResponseField>

<ResponseField name="patient_id" type="string">
  ID of the associated patient.
</ResponseField>

<ResponseField name="provider_id" type="string">
  ID of the assigned provider.
</ResponseField>

<ResponseField name="start_time" type="string">
  Appointment start time in ISO 8601 UTC format.
</ResponseField>

<ResponseField name="end_time" type="string">
  Appointment end time in ISO 8601 UTC format.
</ResponseField>

<ResponseField name="visit_type" type="string">
  The type of visit as provided at creation.
</ResponseField>

<ResponseField name="status" type="string">
  Current appointment status. See [status values](#appointment-status-values).
</ResponseField>

<ResponseField name="notes" type="string">
  Scheduling notes, or `null` if none were provided.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp when the appointment was created.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the most recent update.
</ResponseField>

## Update an Appointment — `PUT /appointments/{id}`

Update an existing appointment to change its status, reschedule the time window, or amend notes. Only the fields you include are changed.

```bash
curl -X PUT https://api.example-ehr.com/v1/appointments/appt_01HYCD5MNP2RW6QK8XJBT4VES \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "start_time": "2024-07-16T14:00:00Z",
    "end_time": "2024-07-16T14:30:00Z",
    "status": "scheduled"
  }'
```

### Path Parameters

<ParamField path="id" type="string" required>
  The unique appointment ID to update.
</ParamField>

### Request Body

All fields are optional. Include only what you want to change.

<ParamField body="start_time" type="string">
  New start time in ISO 8601 UTC format (reschedule).
</ParamField>

<ParamField body="end_time" type="string">
  New end time in ISO 8601 UTC format. Must be after `start_time`.
</ParamField>

<ParamField body="status" type="string">
  Updated status value. Must be a valid status from the
  [status values](#appointment-status-values) table.
</ParamField>

<ParamField body="provider_id" type="string">
  Reassign the appointment to a different provider.
</ParamField>

<ParamField body="visit_type" type="string">
  Updated visit type.
</ParamField>

<ParamField body="notes" type="string">
  Updated scheduling notes. Pass `null` to clear existing notes.
</ParamField>

### Response

Returns HTTP `200 OK` with the fully updated appointment object.

<Note>
  To mark an appointment as `cancelled`, you can either use this endpoint with
  `"status": "cancelled"` or call `DELETE /appointments/{id}` — both produce
  the same result.
</Note>

## Cancel an Appointment — `DELETE /appointments/{id}`

Cancel an appointment. This sets the appointment `status` to `"cancelled"` and records a `cancelled_at` timestamp. The appointment record is retained for audit and billing purposes — it is not permanently deleted.

```bash
curl -X DELETE https://api.example-ehr.com/v1/appointments/appt_01HYCD5MNP2RW6QK8XJBT4VES \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

### Path Parameters

<ParamField path="id" type="string" required>
  The unique appointment ID to cancel.
</ParamField>

### Response

Returns HTTP `200 OK` with the cancelled appointment object. The `status` field will be `"cancelled"` and a `cancelled_at` timestamp will be included.

```json
{
  "id": "appt_01HYCD5MNP2RW6QK8XJBT4VES",
  "patient_id": "pat_01HXB3FKVN8QT5WP2YDMCZ7RS",
  "provider_id": "usr_01HW3NLVMD8PR5TQ9ZBCF2KXA",
  "start_time": "2024-07-16T14:00:00Z",
  "end_time": "2024-07-16T14:30:00Z",
  "visit_type": "follow_up",
  "status": "cancelled",
  "notes": null,
  "cancelled_at": "2024-06-12T08:20:00Z",
  "created_at": "2024-06-10T14:55:00Z",
  "updated_at": "2024-06-12T08:20:00Z"
}
```

<Warning>
  Cancelling an appointment within 24 hours of the scheduled `start_time` may
  trigger a late-cancellation event in connected billing and patient
  communication workflows. Verify your organization's cancellation policy before
  automating same-day cancellations.
</Warning>
