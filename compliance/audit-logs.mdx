Audit logs are a mandatory component of HIPAA compliance. The HIPAA Security Rule (45 CFR § 164.312(b)) requires covered entities to implement hardware, software, and procedural mechanisms that record and examine activity in information systems that contain or use electronic PHI. Your EHR platform automatically captures a comprehensive, immutable audit trail of every significant action taken within the system — so you always have a complete record of who did what, when, and from where.

<Note>
  Audit logs are **immutable**. No user — including organization administrators and platform staff — can edit, delete, or alter any log entry. This design is intentional and required to ensure the evidentiary integrity of your audit trail. If you believe a log entry is inaccurate, contact support to open an investigation.
</Note>

## What Is Logged

Every action that involves creating, viewing, modifying, or transmitting PHI generates a log entry. Non-PHI administrative actions (such as changing notification preferences) are also captured for a complete picture of system activity.

### Logged Event Types

| Event Type | Description | Data Captured |
|---|---|---|
| **Patient Record View** | A user opens or views any part of a patient chart | User, patient MRN, timestamp, IP address, section viewed |
| **Patient Record Edit** | A user creates or modifies any field in a patient chart, including demographics, clinical notes, problem lists, or medications | User, patient MRN, timestamp, field changed, old value, new value |
| **Login / Logout** | A user successfully authenticates or ends a session | User, timestamp, IP address, device/browser, login method (password, SSO, MFA) |
| **Failed Login Attempt** | An authentication attempt fails | Username attempted, timestamp, IP address, failure reason |
| **Prescription Sent** | A prescription is transmitted to a pharmacy via e-prescribing | Prescriber, patient MRN, medication, pharmacy, timestamp, transmission status |
| **Lab Order Placed** | A laboratory order is submitted | Ordering provider, patient MRN, test(s) ordered, lab destination, timestamp |
| **Imaging Order Placed** | A radiology or imaging order is submitted | Ordering provider, patient MRN, study type, imaging center, timestamp |
| **Report / Document Export** | A user exports or downloads a patient record, clinical summary, or report | User, patient MRN (if applicable), export format, timestamp, IP address |
| **User Created / Modified** | An administrator creates a new user account or modifies an existing one | Admin user, affected user, changes made, timestamp |
| **Role / Permission Change** | A user's role or individual permissions are updated | Admin user, affected user, old role, new role, timestamp |
| **Appointment Scheduled / Modified** | An appointment is created, rescheduled, or cancelled | User, patient MRN, provider, old and new appointment details, timestamp |
| **Billing Claim Submitted** | An insurance claim is submitted to a clearinghouse | User, patient MRN, claim ID, payer, timestamp, submission status |

## How to Access Audit Logs

<Steps>
  <Step title="Navigate to the Audit Log Dashboard">
    In the main navigation menu, click **Administration**, then select **Audit Logs**. You must have the **Administrator** or **Compliance Officer** role to access this section. If you do not see Audit Logs in the menu, contact your organization administrator to update your permissions.
  </Step>
  <Step title="Set Your Date Range">
    Use the **Date Range** picker at the top of the Audit Log dashboard to define the time period you want to review. You can select a preset range (Today, Last 7 Days, Last 30 Days, Last 90 Days) or enter a custom start and end date. For compliance audits, select the full period under review.
  </Step>
  <Step title="Filter by Event Type, User, or Patient">
    Use the filter panel on the left to narrow your results:
    - **Event Type** — select one or more event categories from the table above
    - **User** — search for a specific staff member to see all actions taken by that individual
    - **Patient** — enter a patient name or MRN to see all activity related to a specific chart
    - **IP Address** — filter by source IP to investigate activity from a specific location or device
  </Step>
  <Step title="Review Individual Log Entries">
    Click any row in the log table to expand the full details of that event. The detail panel shows all captured data fields for that event type, including a diff view for record edits that highlights exactly what changed. You can copy a permalink to any individual log entry for use in incident reports.
  </Step>
</Steps>

## Filtering and Searching Logs

Beyond the basic filters described above, the audit log search bar supports the following operators for more precise queries:

| Operator | Example | Description |
|---|---|---|
| Exact match | `user:"jane.doe@clinic.com"` | Returns entries where the user field exactly matches the value |
| Wildcard | `patient:"Smith*"` | Returns entries for any patient whose name starts with "Smith" |
| Date range | `date:2024-01-01..2024-03-31` | Filters to a specific date range using ISO format |
| Event type | `event:"Patient Record Edit"` | Returns only the specified event type |
| IP address | `ip:"192.168.1.100"` | Returns all events originating from a specific IP |
| Combination | `user:"j.smith" event:"Prescription Sent"` | Combine multiple operators with a space |

Saved search filters can be stored for repeated use — click **Save Filter** after building a query to name it and add it to your Saved Filters list for quick access during routine compliance reviews.

## Exporting Logs for Compliance Review

You can export audit logs in two formats: **CSV** for spreadsheet analysis and **JSON** for programmatic processing or submission to a SIEM (Security Information and Event Management) system.

<Steps>
  <Step title="Apply Your Filters">
    Use the date range and filter controls to scope your export to exactly the events you need. A targeted export is easier to review than a full unfiltered dump.
  </Step>
  <Step title="Click Export">
    Click the **Export** button in the upper right of the Audit Log dashboard. Select your preferred format (CSV or JSON) and click **Confirm Export**.
  </Step>
  <Step title="Download the File">
    For exports covering fewer than 10,000 events, the file downloads immediately. For larger exports, you will receive an email with a download link when the file is ready — typically within 5–10 minutes. Download links expire after **72 hours**.
  </Step>
  <Step title="Verify the Export">
    Each export file includes a SHA-256 checksum in the filename and a header row with export metadata (organization ID, date range, total record count, export timestamp). Verify the checksum if you need to certify the file's integrity for a regulatory submission.
  </Step>
</Steps>

### Automated Log Forwarding

If your organization uses a SIEM platform (such as Splunk, Microsoft Sentinel, or IBM QRadar), you can configure the platform to forward audit log events in real time via a webhook or syslog integration. Navigate to **Settings → Integrations → Audit Log Forwarding** to configure your endpoint.

## Log Retention Period

All audit logs are retained for a minimum of **7 years**, consistent with HIPAA's requirement that documentation of security policies and procedures be retained for six years from creation or last effective date, and aligning with common medical records retention standards. Logs are stored in the same encrypted, geographically redundant infrastructure as your clinical data.

After 7 years, logs are archived for an additional 2-year period before being permanently deleted, giving you a total accessible history of up to 9 years. You can request older archived logs by contacting support.

<Tip>
  Schedule a **monthly audit log review** as part of your HIPAA compliance program. Focus your monthly review on failed login attempts, after-hours record access, bulk exports, and any permission changes. Document your review findings and retain that documentation as evidence of your ongoing compliance monitoring.
</Tip>
